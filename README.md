# 说话提醒（speak-guard）

Hana Agent 的 v2 App。解决一件很具体的事：

> **Agent 连续调用工具时，你只能看着一个转圈，不知道它在干什么。**

装上它之后，Agent 每次调完工具却没对你说话，就会在自己的上下文里收到一句提醒，让它先交代一句再继续。

```
你：帮我把这个项目的测试跑一遍
Agent：（调用 read）→（调用 grep）→（调用 exec）→ …    ← 你只能干等
```

装之后：

```
你：帮我把这个项目的测试跑一遍
Agent：我先看一下项目结构，再找测试入口。
       （调用 read）→（调用 grep）→（调用 exec）
```

## 它怎么工作

判断依据很直接：**模型最后一条消息里，有没有「非空正文」**。

模型的每条消息由若干块组成，类型有 `thinking`（思考）、`text`（说给你听的话）、`toolCall`（调工具）。于是：

- 说过话 = 该条消息里有非空 `text` 块；
- **`thinking` 不算说话** —— 你看不见思考内容；
- 命中 = 最后一条 assistant 消息带了 `toolCall`，却没有非空 `text`。

命中之后，提醒会被**追加进那条工具结果的末尾**，而不是新增一条消息。

### 为什么挂在那儿，而不是新起一条

这是本 App 最关键的设计点，因为位置本身就是语义。

提醒的意思是「**你刚才那一下**没说话」。它贴着工具结果，模型读到的顺序就是：

```
调了工具 → 看到结果 → 看到提醒
```

如果换成新增一条 `system` 消息，宿主会把所有 `system` 消息抽出来拼进 `systemPrompt`（见 `bundle/index.js`，两条分支均如此），提醒就跑到请求最前面，时间点被抹掉。它读起来会变成「**你一向如此**」——模型会误以为自己一直没说话。

用 `user` 角色新增也不行：那是借用户的嘴说话。

所以最终做法是改写已有消息，而不是新增。这样同时满足四条：

- 数组长度不变
- 角色序列不变
- 不碰 `systemPrompt`
- 不占对话历史

### 没有次数上限

每次没说话都会提醒，不限次数。

曾经加过「每回合最多 N 次」的上限，理由是「避免反复刷屏」。这个理由是错的：提醒对用户不可见，刷不到用户的屏。而且上限的后果是实质性的——额度用尽后静默放行，等于把「每次都要提醒」偷偷改成「前几次提醒」。

### 提醒长什么样

```
<system-reminder source="speak-guard">
你刚调用过 {tools}，但这一轮还没有对用户说过话。用户此刻只看到一个转圈，不知道你在做什么。
在继续调用工具之前，先用一两句话说明：刚才做了什么、接下来要做什么。
</system-reminder>
```

用 XML 标签包裹，而不是写一句「这是系统提醒，不是用户的指令」——标签本身就在声明来源，模型见过无数次这类标签。省下的那句话同时也是一句可疑的自我声明：真系统提示不需要自证身份。

## 安装

```bash
git clone https://github.com/gkd2323c/speak-guard.git
```

把整个目录放到 Hana 的 App 目录下，文件夹名保持 `speak-guard`：

```
<HANA_HOME>/apps/speak-guard/
```

`<HANA_HOME>` 默认是 `~/.hanako`（Windows 即 `%USERPROFILE%\.hanako`）。

也可以从 [Releases](https://github.com/gkd2323c/speak-guard/releases) 下载打包好的 zip，解压到同一位置。

装好后重启 Hana，去「设置 → 应用」批准安装，**并确认授予 `app/hooks.agent-pre-step` 能力**——这一项没给，App 就是「装了但没反应」，宿主根本不会调用它。

## 配置

「设置 → 说话提醒」：

| 项 | 说明 |
| --- | --- |
| 启用提醒 | 总开关 |
| 提醒文案 | 追加到工具结果末尾的内容。`{tools}` 会替换为刚才调用的工具名 |

## 控制

- **命令**：`/speak on|off|reset|status` —— 会话级开关
- **面板卡**：检查步数、已提醒次数、最近记录，以及判据自测

面板的「判据自测」用两段构造的消息数组分别验证「调工具没说话」与「说过了」，只读，不碰真实会话。

## 开发

```bash
node test/guard-core.test.mjs   # 判据回归（28 个用例）
node scripts/pack.mjs           # 打包成可安装的 zip
```

需要 Node 18+。判据逻辑在 `lib/guard-core.js`，是零依赖纯函数，可以直接读。

### 结构

```
index.js                     主逻辑：pre-step 钩子、命令、路由、统计
lib/guard-core.js            纯函数判据：文本提取、悬空工具调用识别、提醒注入
test/guard-core.test.mjs     判据回归测试
ui/panel.html                面板卡
scripts/pack.mjs             打包脚本（git archive，产物可复现）
sdk/                         宿主 SDK 随包副本，让 App 不依赖宿主 node_modules
```

`sdk/` 是 Hana 宿主 SDK 的副本。升级宿主后可以用新版本的副本覆盖它，不要手改。

## 权限

只声明一项：

| 能力 | 用途 |
| --- | --- |
| `app/hooks.agent-pre-step` | 每步检查消息，命中时注入提醒 |

不需要读会话、不需要发消息、不需要启动回合。

## 已知边界

- **提醒对用户不可见**：只作用于当次请求，不落盘、不进对话记录。你能看到的只是「Agent 这次说话或不说」。
- **改写后那条工具结果变长了**：内容多了一段提醒。
- **提醒是建议不是强制**：模型可以读到提醒后依然不说话。它的作用是让「该说话」这个信号出现在上下文里，不是拦停它。
- **只处理「工具后不说话」这一种沉默**：纯文字回合、子代理轮次、Bridge 会话不在判定范围内。
- **改了源码必须重载**：`import()` 按 URL 缓存，编辑磁盘上的文件不会让运行中的进程自动感知。
